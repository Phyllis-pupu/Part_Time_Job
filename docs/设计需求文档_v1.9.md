## 0. 一句话

一个橙光式的像素视觉小说：**你不出现，只有一只手在画面里动。**

七天，凑一千块。撞坏的那台相机，第一屏就压在桌上。

## 2. 表现形态

**橙光式视觉小说 + 像素美术 + 轻经营**

- 一层背景（交叉淡入）+ 一层立绘（呼吸浮动）+ 一层 UI（对话框 / 选项 / HUD）
- 文字逐字机打，点击加速，再点继续
- 选项浮在对话框上方，跟对话框高度联动
- 白天在大厅做选择（花力气换钱，或 0 消耗聊两句），晚上回宿舍结算
- 手机是独立图层：微信聊天、招聘信息、群消息都在这块屏上
- **竖屏优先**：整个舞台是手机屏幕的形状（约 9:19.5），从上到下是「画面 → 选项 → 对话框」，电脑上套一个手机框

## 3. 屏幕与栅格

| 项 | 规格 |
|---|---|
| 画布形态 | **流式竖屏**：`#stage` 撑满屏幕（电脑上收成 414px 宽的手机框，圆角 + 投影） |
| 竖向结构 | `#scene`（flex:1，画面）→ `#panel`（对话框，贴底，`padding` 含 `safe-area-inset-bottom`） |
| 逻辑像素栅格 | **240 × 360**（背景，2:3）；立绘逻辑高 **196px**；手逻辑高 **124px**。所有素材共用这一套栅格 |
| 导出尺寸 | 栅格 2× → 背景 **480×720**、立绘高 **392px**、手 **192×264**（这就是 `assets/` 里的实际尺寸） |
| 背景显示 | `object-fit: contain`，**一张都不裁**；空出的上下用同一张图放大模糊（`#bgFill`，blur 18px / brightness .52）填满 |
| 立绘 | `height: 54%`（占画面区高度），底对齐，居中，`max-width: 92%` |
| 像素放大 | 只用最近邻（`Image.NEAREST` / `image-rendering: pixelated`），禁止平滑 |
| 安全边距 | 左右 10px（对话框）、12px（选项）；顶部 HUD 52px；底部 `env(safe-area-inset-bottom)` |
| 适配 | 360×640 ～ 430×932 都验过；只伸缩不重排，竖屏竖横屏都不提示"转过来" |

**为什么背景是 2:3 而不是 9:16**：手机屏幕比 2:3 更高，2:3 的画面在多数机型上几乎正好铺满；再高出来的部分交给模糊铺底，比强行裁图好。**宁可留虚化，也不裁内容。**

## 4. 视觉语言

### 4.1 色板（全部素材与 UI 共用，禁止跑色）

| 名称 | 色值 | 用途 |
|---|---|---|
| 墨 | `#17150f` | 边框、对话框描边、标题底 |
| 纸 | `#efece4` | 对话框底、追缴面板底、UI 反白字 |
| 朱 | `#b23b2a` | 违法/追缴/警告、闪红、印章色 |
| 金 | `#a8791a`（亮态 `#e9c87e`） | 主按钮、金额、强调 |
| 灰绿 | `#7d8b7a` | 背景环境色（墙、设施） |
| 暗面 | `rgba(10,9,7,.88)` | 大厅板、遮罩 |
| 正文 | `#221f18` | 对话框内文字 |
| 次要字 | `#b3a992` / `#8a7f6b` | 描述、提示 |

### 4.2 像素规范

1. 背景按 **240×360 逻辑栅格**落稿（导出 480×720），不要直接按屏幕尺寸画——先小后放大才有颗粒感。**构图必须是竖的**，横图塞进竖屏只有两条路：裁掉两边，或者上下两条黑边。
2. 立绘抠底成透明 PNG，**不描白边**，靠深色轮廓贴住背景。
3. 所有素材**不含任何文字**（招牌、海报、聊天框一律留空，文字由 UI 层写）。
4. 光源统一从左上打，阴影偏右下落；夜晚场景整体压暗但不加蓝。
5. 边缘抗锯齿会破坏像素感——出图后**不要**做平滑缩放，只用最近邻。

### 4.3 字体与排版

| 位置 | 字号 | 行高 | 字距 |
|---|---|---|---|
| 对话正文 | 16px | 1.66 | .2px |
| 说话人名牌 | 12.5px | — | 1.5px |
| 选项 | 14.5px | 1.5 | .2px |
| HUD | 12px（金额 13px） | — | 0 |
| 标题主字 | 42px | 1.15 | 8px |
| 结局主字 | 30px | 1.25 | 5px |

字号是按 **390px 宽**定的；更宽的屏不放大字号（保持一屏信息量），只把左右留白撑开。

字体族：`-apple-system, "PingFang SC", "Noto Sans SC", monospace`（等宽兜底，保证像素感不被行楷破坏）。

**空行即分段**：数据里的 `\n\n` 渲染成一个段间距，`\n` 单独换行。一段不超过 40 字，一次最多 3 段。

## 5. UI 组件规格

| 组件 | 位置（竖屏，390 宽基准） | 规格 |
|---|---|---|
| **HUD** | 贴顶 52px，浮在画面上 | 左：`第 N 天 · 周X`；体力条 56×8 + 数字；右：`¥余额 / 1000` + `眼力 n/8` 胶囊。序章与标题时 `opacity:0` |
| **画面区** `#scene` | 顶 0 到底部对话框上方 | 里面依次是：模糊铺底 → 主图（contain）→ 压暗层 → 立绘 → 手 → 手机；`overflow:hidden` |
| **对话框** `#panel`+`#dlg` | 贴底，左右 10px，最小高 126px | 纸底 + 2px 墨边 + 2px 灰边投影；内边距 20/16/16；`max-height:46vh` |
| **正文区** `#text` | 对话框内 | `max-height:calc(46vh - 66px)`，超出滚动；追缴时切 `.tall`（`max-height:80vh`，内部再滚） |
| **名牌** `#name` | 对话框左上，`top:-15px` | 墨底反白；**`#dlg` 必须 `overflow:visible`，否则名牌被裁一半** |
| **继续提示** | 对话框右下 | `▼`，打字中隐藏 |
| **选项** `#opts` | 绝对定位，`bottom = 对话框高度 + 8px` | 单列，左右 12px，压在画面下半部分的立绘上；`placeOpts()` 实测面板高度后摆放 |
| **大厅** `#hub` | 顶 52px 到底，左右 12px，底部留 78px 给按钮 | **单列**卡片；内容多时可滚，底部 96px 渐隐；底部固定「今天就到这儿」 |
| **手机** `#phone` | 居中，宽 66%，比例 9:14 | `card` 节点渲染成一张通知卡片（群名 / 时间 / 99+ / 预览两行） |
| **追缴面板** `.confisc` | 对话框内 | 纸底 + 朱边；`违法所得 · 依法追缴` / `−¥xxx 一分没留下` / 三句说明 |
| **日卡** `#daycard` | 全屏 | `DAY N` + 标题 + 差额，1.25s 自消 |
| **标题页** `#title` | 全屏 | 竖版校园主路做底（压暗 58%），主标题 + 三行规则 + **一个**主按钮 |
| **结局页** `#ending` | 全屏滚动 | 结局名 / 题眼 / 结算数字 / 8 个眼力项 / 逐日复盘 / 老陈三句话 / 再来一次；全部单列 |
| **眼力抽屉** `#sheet` | 全屏遮罩 | 点 HUD 的「眼力 n/8」或按 `E` 打开 |

**关于标题页只有一个按钮**：主按钮的文案随存档变化——没存档是「开始这七天」，有存档是「继续 · 第 N 天」；「从头开始」降级成下面一行小字链接。**同一个位置永远只有一个主操作。**

| 文件 | 用途 | 规格 |
|---|---|---|
| `cg_cover.png` | 标题页封面（v1.1 已改用 `bg_campus`，此图留档） | 480×270，静物：桌上的相机 + 七张钞票 + 手机 |
| `cg_lens.png` | 序章「镜头碎了」CG | **480×720**（竖版），碎裂镜头躺在水磨石地上、窗口斜光，配闪白 + 震屏 |
| `hand_open.png` | 「你伸手」 | 192×264，掌心朝外，四指张开，从画面右下方伸入 |
| `hand_take.png` | 「你抓住」 | 192×264，四指半屈、拇指收拢，正在松开/抓住的瞬间 |
| `hand_fist.png` | 「你握拳」 | 192×264，握紧，四个指节朝上 |

三只手由 ImageGen 出图（白底），`tools/prep_hand.py` 负责**抠白底 → 只留最大连通块（去掉模型顺手画的小装饰）→ 统一高度 124 逻辑像素 → 贴到 96×132 画布底部居中**。三张共用同一画布，切姿态时手不会跳。
> 早先用 `draw_hand.py` 拿胶囊体拼过一版，形状像连指手套，弃用；脚本留在 `tools/` 里备查。

手的三态由序章的 `hand:'open'|'take'|'fist'` 字段驱动：从画面下方推入（`bottom` 从 -42% 到 -8%，0.5s），2.6s 自动收回；`z-index:5`，在立绘之上、对话框之下，**默认落在右侧靠里**，像是「你」从右下方伸手去够桌上的东西，不会正好盖住画面中心。

## 10. 场景映射机制

画面与剧情分离。剧情在 `data.js`，画面在 `scenes.js` 的 `SCENE` 表：

```js
window.SCENE = {
  d1_am:        ['bg_office', 'zhouli'],       // [背景, 立绘, 表现]
  d1_night:     ['bg_dorm', '', 'phone'],      // 第三位 'phone' = 手机图层
  d1_night2:    ['bg_dorm', 'mama', 'phonecam'], // 妈妈的立绘带通话框
  epi_mule:     ['bg_police', 'jingcha'],
};
```

**兜底规则**（表里没写时按前缀猜，新增节点可以先不填）：

| 前缀 | 背景 | 立绘 |
|---|---|---|
| `dN_hub` | 宿舍 | 无 |
| `j_*` | 宿舍 | 按 `who` 查 `CHARFILE` |
| `k_*` | 宿舍 + 手机 | 按 `who` |
| `epi_*` | 派出所 | 办案民警 |

改画面**只改这张表**，不碰引擎。

## 11. 动效与反馈

| 触发 | 效果 | 时长/参数 |
|---|---|---|
| 换背景 | 双层交叉淡入（`bgA`/`bgB` 轮换） | 40ms 后旧层淡出，CSS `opacity .5s` |
| 立绘进场 | 自下 12px 推入 + 轻微浮动 | `.on` 动画 260ms；`bob` 循环 3.2s |
| 手 | 从右下推入，2.6s 收回 | `bottom` -42% → -8%（0.5s）+ `opacity` |
| 打字机 | 20ms/2 字；点击立刻补全并继续 | 跳过时必须**把整段渲染完并触发后续回调** |
| 震屏 | 舞台 ±4px 抖动 | 520ms |
| 闪白/闪红 | 全屏色层 | 420ms `ease-out`，涉罪闪 `#b23b2a` |
| 进账/扣钱 | 金额飘字，金/朱两色 | 1.1s 上浮淡出 |
| 日卡 | `DAY N` 淡入停留 1.25s | 期间不可操作 |
| 选项 | hover 右移 4px + 边框转金 | 120ms |
| 追缴 | 面板从正文下方长出 + 金额飘红 | 与打字机同在 `#text` 内 |

### 14.1 换一张图（最常见的操作）

1. 生成新图，丢进 `pixel/raw/`，文件名带时间戳（如 `2026-11-03T07-48-36.png`）。
2. 在 `tools/prep.py` 顶部的 **`BG`** 表（背景/CG）或 **`CHAR`** 表（立绘）里加一行：
   `('原图时间戳.png', 'bg/bg_xxx.png')`。
3. `python3 tools/prep.py` —— 自动切留白 → 抠底 → 裁切 → 压到 240×135 栅格 → 2× 导出到 `assets/`。
4. 若是新角色，在 `js/scenes.js` 的 `CHARFILE` 里加「说话人 → 文件名」，再在 `SCENE` 表里把节点指过去。
5. `python3 tools/build_single.py` 重新打包单文件版。

**处理管线（`prep.py` 内部，出问题时照这个查）**

| 步骤 | 背景 | 立绘 | 手 |
|---|---|---|---|
| 1 | `wipe_watermark()` 用上方等高带镜像，抹掉右下角「AI生成」水印 | `key_bg()` 从四角泛洪抠底（边框中位色 ±62 + 亮度/饱和度兜底） | `key_white()` 从四边泛洪抠白底，再把全图近白像素一并清掉（去白毛边） |
| 2 | `to_ratio(2/3)` 居中裁成 2:3 | 剥 8 层与透明区相邻的浅色像素 | `largest_blob()` 只留最大连通块 |
| 3 | `pixelize()` → 240×360 → 量化 64 色 | `trim()` → 统一逻辑高 196 | `trim()` → 统一逻辑高 124 |
| 4 | 最近邻 2× 导出 480×720 | 2× 导出，高 392 | 居中贴到 96×132 画布底部，2× 导出 |

### 14.2 加一段剧情

1. 在 `data5.json` 加节点，`options[].go` 指向下一个节点。
2. 在 `scenes.js` 加一行 `新节点id: ['bg_xxx','角色', '']`（不加也能跑，有兜底）。
3. 重跑数据生成脚本 → `js/data.js` → `build_single.py`。

### 14.3 素材生成提示词模板

```
16-bit pixel art, [场景/角色描述], limited palette:
#17150f #efece4 #b23b2a #a8791a #7d8b7a,
dithering, hard edges, no anti-aliasing,
[背景: vertical portrait composition, 2:3, room interior, lower third empty for the character, no text, no people]
[立绘: full body portrait, transparent background, facing camera 3/4, dark outline]
```

**必须**：`no text, no watermark, no UI, no anti-aliasing`。出图后仍会带一圈画布留白和棋盘格底，`prep.py` 会处理：
- `_last_art_row()` 要求连续 3 行有内容才算画面结束（防止被边框线骗）
- `key_bg()` 用「边框中位色 ±62」+「亮度/饱和度」双判据泛洪抠底，再剥 8 层棋盘格
- `cut_blank_band()` 循环切 4 次，处理多层留白

## 18. v1.2 修了什么（开局点不动的那个 bug）

**现象**：标题页点「开始这七天」，画面停住 —— 标题消失了，顶部状态栏亮着，底下什么都没有，点什么都没反应。

**原因**：`startGame()` 的第三行是裸的 `localStorage.removeItem('jzs_save')`，没有包 try/catch。
只要 localStorage 不可用 —— iOS Safari 直接用「文件」App 打开本地 HTML、隐私/无痕浏览、
微信等内嵌 webview 禁用本地存储 —— 这一行就会抛 `SecurityError`。
而此时标题层已经被隐藏、HUD 已经点亮，`renderHub()` 永远走不到，于是停在「有 HUD 没有内容」的死画面。
`readSave()` 本来就是带 try/catch 的，所以标题页看起来一切正常，一点就死 —— 这也解释了为什么只有点击后才出问题。

**修法**（四层，缺一层都可能复发）：

1. **所有 localStorage 调用统一走 `LS.get / LS.set / LS.del` 安全包装**，不可用时静默降级为不存档，不影响流程。
2. **调整开局顺序**：先 `reset()` 结算状态，再切画面，最后播日卡。任何一步失败都不会停在黑屏上。
3. **日卡不再是阻塞过场**：进大厅时先把 `renderHub()` 铺好，日卡只是盖在上面的一层；1.25s 后自动揭掉，
   期间**点一下屏幕立刻跳过**。哪怕定时器被浏览器节流，玩家总能进到大厅。
4. **兜底**：`window.onerror` 全局捕获 + `enterDay()` / `resumeGame()` 局部 try/catch，
   进不去大厅就重开当天，而不是静默死掉；存档读坏了自动从第一天重来。

**顺手加的防御**：

- 标题页封面和渐隐层加 `pointer-events:none`，按钮所在的 `.box` 提到 `z-index:2` —— 保证任何浏览器里按钮都点得到。
- 按钮的 `onclick` 里 `stopPropagation()`，避免点击冒泡到舞台后被「跳过日卡」的逻辑吃掉。
- 新增 `tools/diag.py` 诊断脚本：headless 跑完整链路（推完序章 → 点开始 → 进大厅 → 点一个岗位 → 结算回大厅），
  并可用 `DIAG_NOLS=1` 模拟 localStorage 抛错的环境做回归。

**回归结果**：正常环境与 localStorage 抛错环境，两条链路都走通 ——
点击开始 → 大厅 24 个按钮全部渲染 → 点「快递驿站分拣」进对话 → 自动推进 → 钱到账回大厅（岗位消失、列表刷新）。

## 19. 逐句对话 + 自动播放（v1.2 追加）

### 19.1 为什么要改

原来一个节点的台词是一整段 `text`，里面用 `\n` 分了几层，打字机直接全打出来塞进对话框 ——
一屏五段话，玩家的眼睛不知道先看哪句，节奏也就没了。改成橙光的做法：**一次给一句，玩家点一下给下一句**，不想点就开自动。

### 19.2 一句怎么切

`splitBeats(text)`：

1. 先按换行拆 —— 作者在 `data.js` 里已经把每个自然段用 `\n` 分开了，这是主依据。
2. 单段仍然超过 54 字时，再按 `。！？` 和 `……` 二次切，避免长旁白一句顶满一屏。
3. 空行直接丢掉，不会出现「点一下没字」的空拍。

### 19.3 播放状态机

```
playText(text, done)
   └─ showLine()           取第 i 句
        └─ type(句)         打字机逐字
             ├─ 不是最后一句 → lineWait = true，显示 ▼，排自动定时器
             └─ 是最后一句   → 调 done()（弹选项 / 交给序章推进）
```

点击（或空格）走 `advanceLine()`，只有三种结果：

| 当前状态 | 点击效果 |
|---|---|
| 正在打字 | 把这一句补全（不跳句） |
| 打完了、还有下一句 | 出下一句 |
| 已经是最后一句 | 不吞点击，交回上层（序章推进 / 等选项） |

这样点得快也不会漏句，点得慢也不会一次出一大段。

### 19.4 自动播放

- 右上角悬浮按钮 `▶ 自动`（`#autoBtn`，在 HUD 下面、画面右上，不压任何正文）。开启后变金色 `Ⅱ 自动开`。
- 每句打完停 `560ms + 字数 × 24ms`，上限 1.5 秒 —— 短句不拖，长句留出读的时间。
- **碰到选项一定停**：最后一句打完不会有下一句，自动链自然中断。
- **只有一个「……」的纯推进选项**（全剧 28 个）自动点掉，否则自动会卡在这种节点上；
  只有一个选项但文案是真实选择的（另有 28 个），照停不误。
- 序章也吃这套：beat 之间自动往下走，走到「……我先想想 / 不用」那个选项停住。
- 自动模式打字速度提到 3 字/帧，普通模式 2 字/帧。
- 键盘 `A` 可以开关自动（`空格` 推进、`E` 眼力、`1–4` 选项）。

### 19.5 顺带解决的布局问题

逐句显示会让对话框高度每句都变，`#panel` 一变高，`#scene` 就变矮，`contain` 的背景会跟着缩放 —— 画面看起来在抽。
所以把对话框改成**固定高度**：`min-height: clamp(126px, 17.5vh, 152px)`，文字多时 `#text` 内部滚动。
一句和三句一样高，背景一动不动，选项也不会跟着抖。

### 19.6 验证

用 `tools/diag_lines.py <节点id>` 跑两段：

- **手动段**：进 `ev_wanghao`（5 句），逐次点击，确认 `at` 从 1 走到 5、每句正文不同、第 5 句打完弹出两个选项。
- **自动段**：同一节点开自动，1.4s→2.6s→3.8s→5.0s→6.2s 逐句推进，7.4s 弹选项后**不再动**。

序章单独跑了一遍：开自动 15 秒从 beat 1 走到 beat 11，停在「他看着你。等着。」的那个选项上，没有继续往下吞。

### 20.1 上一版哪里不对

v1.2 的大厅是一张铺满屏幕的深色列表：最上面四行旁白、两组小标题（`⚡ 0 · 不花力气` / `花力气 · 干完给钱`）、
下面七八张带描述的长卡片。问题有四个：

1. **把画面吃掉了**。list 有一层 `rgba(8,7,6,.93)` 的底，宿舍图只剩一层模糊的黑影，
   等于白做了一张背景。
2. **体力看不见**。列表从 y=52 铺到底，玩家的视线里根本没有「还有 60 点力气」这件事，
   只有卡片右下角那个 `⚡ −34`。
3. **旁白还是「一大段」**。v1.2 给对话框做了逐句，大厅却仍是整块文字堆在顶上，两套节奏。
4. **两组小标题是给开发者看的**，`不花力气` / `花力气 · 干完给钱` 既不是玩家的话，也占地方。

## 21. v1.4：四件事（大厅收尾 / 说话人 / 去干点不动 / 头像）

### 21.1 剧情放完就不要挂着

v1.3 的做法是「当天第二次进大厅只留最后一句旁白」——本意是别逼人重看，
结果是从剧情回到大厅时，那一句旁白又出现在对话框里，看起来就像**剧情没放完、卡在那儿了**。
玩家截图里那句「挂了电话，他把新手机往兜里一塞……」，其实是当天大厅的开场旁白最后一句。

改成：**旁白只放一次，放完就收。**

- 当天第一次进大厅：`playText()` 一句一句放。最后一句打完，右下角出现「点右边接活 · 点下面聊两句」，
  再点一下 → `hubBare()`：整个对话框（含名牌）收掉，`#hubTip` 接上，只留一行灰字。
- 之后无论是干完活回来、聊完天回来、还是重开这一天：`renderHub()` 直接走 `hubBare()`，
  **对话框压根不亮**，屏幕上只有场景、图标、头像和那行提示。
- 开着自动播放时，最后一句停下 1.4 秒后自己收掉，不用等玩家点。
- 点空白处 = 收起（先把兼职卡关掉，再收对话框）。
- `hubSeen` 写进存档，读档回来也不会重放。

### 21.2 名牌要跟着句子走

数据里一个节点的 `who` 是「对面那个人」，但 `text` 里往往混着三种东西：
旁白、对方的话、**你自己的话**。v1.3 把 `who` 从头挂到尾，于是你说的话上面也写着「王浩」。

改成逐句判 `speakerOf()`，规则按可靠度排：

| 句式 | 判给谁 | 例 |
|---|---|---|
| `你：……` 开头 | 你（这个前缀顺手抹掉，名牌已经写了） | `你：探店一分半，现在什么价。` |
| 以 `「` 开头的纯台词 | 眼前这个人（若上一句是「某某说：」这种引子，跟着引子走） | `「就……帮人走个账，跑个腿。」` |
| `某某：「……」` | 看冒号前那半句的**主语**：你 → 你；他/她/名字 → 眼下这个人；没有主语 → 旁白不挂牌 | `你把椅子转过去：「你那个活，到底是干什么的。」` |
| `你说 / 你问 / 你回 / 你答 / 你喊` | 你 | `你说没有。` |
| 其余 | 旁白，不挂牌子 | `他正在拆快递，手停了一下。` |

主语怎么取：只取冒号前**第一个分句**，先削掉「然后 / 半分钟后 / 挂之前 / 过了半分钟」这类时间状语，
再看开头第一个「你 / 我 / 他 / 她」。这样 `然后他把手机扣在桌上，抬眼看你：「……」` 判成**他**，
不会被句子里的「看你」带歪成你。

还有一类靠句式完全判不出来的：对谈节点一上来就是一句引号（`「走什么账。」`），
两边都可能是说话人。这种按「第几句」点名，写在 `SPK_FIX` 里：

```js
const SPK_FIX = {
  ev_wanghao_q:  { 0: '你', 3: '你' },   // 你问「走什么账」「卡是谁的」
  ev_wanghao2_q: { 3: '你' },            // 你问「转给谁」
};
```

全剧 485 句的分配结果：**你说 11 句、对方 128 句、旁白 346 句**，没有一句「是引号却没名牌」。
名牌上写「你」时底色偏金（`.me`），同时把对面那张立绘压暗一档（`#char.dim`）——谁在说话一眼能看出来。

### 21.3 「去干」点不动

**根因**：`#hub` 整层为了「点空白处推进旁白」设了 `pointer-events:none`，
子元素只有 `#jobRail` / `#chatRow` / `#endDayBtn` 各自写了 `pointer-events:auto`，
**唯独漏了 `#jobPop`（兼职详情卡）**。所以卡片看得见、按不动 —— 手指点下去穿到舞台层，
被当成「点空白」，什么也不会发生。

这也解释了为什么之前的自动化测试全绿：脚本里 `document.getElementById('jobGo').click()`
是程序调用，**不走命中测试，绕开了 `pointer-events`**。

修法：`#jobPop{pointer-events:auto}`，并让卡片自己 `stopPropagation()`（点卡片本体不会把卡片关掉，
点卡片外面才关）。验证方式换成 `document.elementFromPoint(按钮中心)` —— 现在返回的就是 `BUTTON#jobGo`。

### 21.4 头像被圆圈切掉

v1.3 用 `height:400%` 把立绘塞进 50px 圆里，只露出立绘最上面 12% —— 那是一撮头发。
现在改成**先按「头」裁一张方图**（`assets/face/*.png`，160×160），再 `object-fit:cover` 进圆里。

`tools/make_faces.py` 的裁法：

- 立绘统一是 392 高的半身像，方形边长固定取 `0.38 × 392 ≈ 148` —— 10 张脸在头像里一样大。
- 顶端留 1.2% 的余量，别让头发贴着圆边。
- 横向中心用**头部那几行（顶端往下 28%）的中线**，并且把宽度明显超出中位数的行剔掉 ——
  抬手举手机（王浩）、托腮、图边扫描残留都不会把脸带偏。
- 缩放用 `NEAREST`，保住像素块的硬边。

### 21.5 顺手改的

- 一天 5 个以上兼职缩一号（56px），7 个以上再缩一号（50px）。
  第 6 天 7 个图标 + 收工在 360×640 上一列排得下，最后一个不再被裁掉半个。
- `#hubTip` 单独一层（30px 高），和图标栏、头像一起用 `hubLayout()` 跟着对话框高度走。
- 对话里点空白：先关兼职卡 → 再收大厅旁白。

### 21.6 验证

新增 `tools/diag_spk.py <节点id>`，一次跑三段：

1. 大厅：开头 `dlg=true tip=false` → 旁白点完 `dlg=false tip=true`；
2. 兼职：`elementFromPoint` 打在「去干」「再想想」中心，现在都命中按钮本身；
3. 逐句：进节点一路点，打印每一句的「名牌 + 正文 + 模式」。

抽查结果：

| 节点 | 结果 |
|---|---|
| `ev_wanghao` | 旁白 → **你**（你把椅子转过去：「……」）→ 旁白 → **王浩** → **王浩** |
| `ev_wanghao_q` | **你**「走什么账。」→ 旁白 → **王浩** → **你**「卡是谁的。」→ **王浩** |
| `ev_clip_dm` | **你**（`你：` 前缀已抹掉）→ 旁白 → **私聊 · 阿 May** ×3 |
| `ev_mom_pride` | **妈妈** → **妈妈** → **你** → 旁白 → **你** |

`diag.py`（正常 + localStorage 抛错两套环境）、`diag_hub.py`（点图标 → 看卡 → 去干 → 结算回大厅 → 聊 → 重听 → 收工）、
`walk.py`（自动跑完七天，`63.20 → 138.20 → 203.20 → … → 13.20`，进「没凑够」结局）全部通过，无 JS 报错。

## 22. v1.5：界面上的字，直接画出来

### 22.1 问题

数据里原本这样写：

> 半分钟后弹出一个框：「填写手机号，立即领取任务」。
> **框底下一行小字：「我们会对您的信息严格保密。」**

这是在用旁白**描述画面**。读者要在脑子里先搭一个网页，再去看那行小字。
剧本提示混进了小说，节奏就断了。同类写法还有「页面顶上三行加粗的字：」「她用笔尖点着一行：」
「后面跟一张照片：卷子右上角，红笔写着 112」。

### 22.2 做法

新增一层 `#note`（在 `#scene` 内，`z-index:6`），显示**画好的 PNG**。
图里的字是烘焙死的，剧情里只留一句最短的引子。

```
数据：nodes[id].note = 'note_adpage'
引擎：paintScene() → setNote(n.note) → <img src="assets/note/note_adpage.png">
```

规则：

- 一个节点一张图，节点开始时出现，离开节点 / 回大厅 / 进结局时收掉（`hubBare`、`showEnding`、`showTitle` 各清一次）。
- 图出现时不再叠那个 DOM 手机壳（`setPhone` 让位给 `setNote`）。
- **选项弹出来时图自动收一号**：`fitNote()` 量一下 `#opts` 的实际上沿，把被盖住的高度
  折成 `#note` 的下边距（换算时除掉 stage 的缩放比）。按钮有多高就收多少，
  否则会压住图最下面那行小字 —— 也就是这次要给人看的那行。
- 图用 `object-fit:contain`，上下留 9vh 避开 HUD，绝不裁切。

### 22.3 三类外观（`tools/make_notes.py`）

| 类型 | 用在哪 | 规格 |
|---|---|---|
| `phone` | 广告落地页、群通知、推送、客服窗口、系统提示 | 588×自适应，黑边机身 + 状态栏 + 导航栏 |
| `paper` | 面单、打印纸、问卷、通报、撕掉的招工纸、卷子 | 620 宽，米白纸 + 断角 + 折痕 + 可选红章 |
| `card` | 96110 反诈卡 | 620×380，深蓝底 |

全部按 **2 倍尺寸绘制**（画布 620），游戏里显示到 310–340 之间，正文 26px → 屏上 13px。
字体 `Hiragino Sans GB`，`quantize(64)` 压色，保证和像素背景同一套色调。

| 「该说。」 | 老板娘 ❌ | **你** |

| 中午她转来 90：「不好意思啊…」 | 你 ❌ | **阿 May** |
| 视频里那个人说：「学业退费…」 | 上家 ❌ | 旁白（不挂名） |
| 「叮」——100。 | 妈妈 ❌ | 旁白 |

三处改动：

1. `subjOf()` 改成**从冒号前最后一个分句往前找**：先认句首代词，再认句中代词
   （排除「看你 / 给你 / 让**你**」这种宾语位）。一句话里既有旁白又有引语时不会认错。
2. 冒号前没有主语、但含言说动词（说 / 问 / 答 / 回 / 喊 / 补 / 开口 / 低声）→ 归当前角色；
   否则就是画面上的字，不挂名牌。
3. 句式判不出来的，写进数据：`nodes[id].spk = { "0": "你", "2": "" }`（`""` = 旁白）。
   引擎先读数据，再退回启发式。**改文案时和文案一起改，不再藏在引擎里。**

另外 `splitBeats()` 加了一条：引号没闭合就不切句。
以前超过 54 字的「小满啊，李哥这儿有个轻松的活儿。……」会被劈成四段，前三段没引号，
名牌就飘了。

## 23. v1.6：声音

### 23.1 为什么不是音频文件

整个游戏是一个 HTML 文件，图片已经 3.6 MB 内联进去了。再塞十几个 mp3，
文件会翻倍；而且换一台设备、换一个浏览器，编码支持还不一样。

所以这一版的声音是**现场合成的**：`js/sfx.js` 里用 Web Audio 的
振荡器（方波 / 三角波 / 正弦）和一小段白噪声，按需拼成每一个音效。
零素材、几乎零体积增长（`sfx.js` 一共 11 KB，占单文件的 0.3%），
音色朴素，反而和像素画是一路的。

代价是：音色不如真采样「有质感」。这条我们在文档里认下来——
真要更像橙光，下一步是换成录好的音效包（见 23.6）。

### 23.2 结构

```
sfx.js  →  window.SFX.play('coin')
engine.js 只调名字，不知道声音是怎么发出来的
```

`SFX` 内部三层：

```
每个音效 ──▶ sfxBus(0.5) ─┐
                           ├─▶ master(0.85) ─▶ 压缩器 ─▶ 输出
环境底噪 ──▶ bgmBus(0.85) ─┘
```

中间挂了一个 `DynamicsCompressor`（阈值 −16 dB，比率 3:1）。
短音一个接一个叠起来时，没有它容易糊成一团。

`engine.js` 里有一行兜底：

```js
const SFX = window.SFX || { play(){}, toggle(){return true}, bgm(){}, ... };
```

`sfx.js` 万一没加载、或者浏览器没有 Web Audio，游戏照跑，只是没声音。

### 23.3 音效表

| 名字 | 什么时候响 | 声音 | 设计理由 |
|---|---|---|---|
| `tick` | 台词逐字显示 | 极短三角波，1080–1600 Hz 随机，音量 0.028 | 每 4 帧响一下（≈每分钟 300 次的上限），太密像电报 |

| `pay` | 钱出去（含追缴） | 415→262 Hz 锯齿波 | 往下掉 |

| `bad` | 一步涉罪 | 116→62 Hz 锯齿 + 噪声 + 233 Hz 一点尖 | 和红闪、画面抖同步，是最重的一个音 |

所有音都落在 C 调五声 / 大三和弦上，随便两个撞在一起也不会难听。

### 23.4 环境底噪

一层雨 + 一个低频垫，音量压得很低：

- 雨：白噪声 → 带通 1500 Hz（Q 0.55），增益 0.05，再用 0.06 Hz 的 LFO 让它在 ±0.016 之间起伏。
- 垫：A1 / E2 / A2 三个正弦，增益 0.02 / 0.013 / 0.009，各自带一点失谐和慢速颤音。

合计峰值约 0.09，经过总线后大约 −26 dB——是「房间里的空气」，不是配乐。
进结局时 0.6 秒淡出，点「再来一次」再接回来。

### 23.5 三个容易踩的坑

1. **移动端必须由手势建 AudioContext。**
   页面一加载就 `new AudioContext()`，iOS Safari 会给你一个 `suspended` 的上下文，
   之后所有声音都是哑的，而且不报错。所以：
   `pointerdown / touchstart / keydown` 第一次触发时才 `init()`，并且 `resume()`。
   `#sndBtn` 的点击处理里也显式 `SFX.init()`。

2. **静音要真的不发声，不只是把音量拧到 0。**
   `tone()` / `noise()` 开头就 `if (!ctx || muted) return;`，
   连节点都不建。`tools/diag_snd.py` 专门数了这个：静音期间新增振荡器必须是 0。
   只把 gain 设 0 的话，485 句台词的字数照样在后台建节点，手机上会烫。

3. **开关按钮不能吃掉舞台的点击。**
   声音键和「自动」键都挂在 `#stage` 上，所以两个 `onclick` 都 `stopPropagation()`，
   否则点一下音量，台词会顺带翻一句。

### 23.6 界面上的位置

新增 `#sndBtn`：30×24 的小方块，里面三根由矮到高的竖条，静音时压暗并划一道
红斜杠（从左上到右下，和系统音量图标一个方向）。

- 位置：左上角 `10px / 58px`，正好在 HUD 下面；「自动」键让到 `46px`。
- 层级 `z-index:21`：**标题页和结局页也压得住**（那两层是 20），
  日期卡（22）和眼力抽屉（24）盖住它——那两个是模态，期间不需要调音量。
- 状态存 `localStorage['jzs_snd']`：`'0'` = 静音。下次打开还是静的。
- 键盘 `M` 也能切。

## 24. v1.7：背景音乐 + 三处「点了没反应」

这一版两件事：把雨声换成**会随剧情变化的轻音乐**，
以及修掉三处「明明写好了，玩家点下去却没反应」的地方。

### 24.1 背景音乐：七首，现场弹

还是不做音频文件（单文件已经 3.6 MB）。`js/sfx.js` 里多了一个小作曲机：
一首曲子就是四个参数 —— 速度、四小节和弦、右手琶音型、一小段旋律动机。

```js
daily: {
  bpm: 76, lead: 'piano',
  chords: [[36,60,64,67], [45,57,60,64], [41,53,57,60], [43,55,59,62]],
  arp: [0,2,1,3,2,1,3,2],
  mel: [[0,76,3], [3,79,2], [5,76,2], ...],
}
```

- **和弦**直接写 MIDI 音高：第 0 个是低音，后面是和弦内音。这样旋律能跟和弦对得上。
- **琶音**是一小节 8 个八分音符的格子，每格写「弹和弦的第几个音」，`null` 就是留白。
- **旋律**是 `[第几格, MIDI, 占几格]`，四小节一循环。

一个前瞻调度器每 90 ms 跑一次，把未来 0.5 秒的音符排进 `AudioContext` 的时钟：

```js
while (mClock < ctx.currentTime + 0.5) { playStep(tr, mStep, mClock, layer, sd); mStep++; mClock += sd; }
```

节拍由音频时钟说了算，`setInterval` 抖动、掉帧、切后台都不会让节奏飘。
切后台回来时如果 `mClock` 落后太多，直接跳到当下，不「补课」——
否则一回到前台会有一串音符同时炸出来。

乐器都是合成的：钢琴（三角波 + 二倍泛音 + 快衰减）、
音乐盒（正弦 + 三倍泛音）、铺底（两根失谐三角波，1.1 秒慢起音）、
低音（正弦过低通）、心跳（98→42 Hz 的下滑）、沙锤（高通白噪声）。

### 24.2 哪场戏弹哪首

引擎只报「情绪名」，`SFX.music(mood)`；同名不重来，所以一段戏里翻二十句台词，
音乐是连着走的，不会每句重头放一遍。

| 曲子 | 速度 | 用在 | 听感 |
|---|---|---|---|
| `title` | 66 | 标题页、封面 | 音乐盒，稀疏，像清晨 |
| `daily` | 76 | 宿舍 / 教室 / 校园 / 大厅 | 钢琴 + 琶音，最中性的一首 |
| `phone` | 86 | 广告页、群、推送、客服、私聊、刷单、走账 | 小调，音更短更硬，心里提起来 |
| `work` | 98 | 驿站、奶茶店、商场、食堂、路边、校门 | 大调、稍快，多一层沙锤 |
| `home` | 60 | 妈妈的每一通电话 / 视频 | 只有钢琴，音和音之间留着空隙 |
| `night` | 54 | 每一个 `*_night` 节点 | 很稀的音乐盒高音挂在低音垫上 |
| `tense` | 58 | 民警、办公室、`epi_*`、进看守所 | 小调、低、一声一声的心跳 |

判定顺序（`moodOf(id, bg)`）：

```
1. MOOD_FIX 里点名的节点（妈妈 / 深夜 / 手机 / 被抓）直接给
2. n_jail、epi_*            → tense
3. k_*、j_brush/j_courier/j_cash/j_mule → phone
4. 背景是 bg_police / bg_office        → tense
5. 背景是 站点/奶茶/商场/食堂/街/门    → work
6. 其余                                 → daily
```

换曲是交叉淡入淡出：旧的一层 0.9 秒收掉，新的一层 1.6 秒淡进来。
曲子从第一小节重新开始——换场本来就是换段落，硬接着上一首反而别扭。

结局仍然**收掉所有音乐**，只留那一个四音和弦。这是刻意的：
整部戏唯一安静下来的地方。

### 24.3 「班级群的消息打不开」

第 1 天晚上那张「班级群（37）99+」的卡片，数据里本来就写着：

```json
{ "type": "chat", "from": "班级群（37）", "badge": "99+", "open": "d1_read" }
```

`open` 指向辅导员那条八百字通告。**但引擎从来没接过这个字段**——
卡片只是个死图，玩家点它没有任何反应。

更糟的是：`#phone` 这一层没设 `pointer-events`，
所以它把点击**吞掉了**——点手机不翻台词，点旁边才翻。玩家会觉得「这游戏卡住了」。

```js
el.phone.onclick = c.open ? (e) => { e.stopPropagation(); SFX.play('tap'); renderNode(c.open); } : null;
```

卡片底下加一行会呼吸的金色小字「点一下 · 看全文 ›」，卡片描边同时提亮。

### 24.4 眼力八个，点了不涨数

### 24.5 手机屏里应该是真的聊天记录
